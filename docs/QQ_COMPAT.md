# QQ 接入兼容

对照 company_bot_codex 的 QQ 适配实现，酒馆支持以下消息与媒体流程。角色、人设、状态和工具权限继续由酒馆管理。

## 群消息与引用

- 支持群内 @ 消息、私聊消息及 QQ 推送的全量群消息；兼容 group_openid/group_id、member_openid/user_openid/id、附件 url/src 与缺省图片 MIME。
- 自动去掉 QQ 的 `<@...>` 标记，@ 后的 `/角色` 等指令可正常识别。成员身份始终取 QQ 的身份字段。
- 识别嵌套引用、message_type=103、msg_idx/ref_msg_idx 和 message_scene.ext，以及引用正文中的 QQ 图片附件描述。仅从引用附件描述提取受限 QQ CDN 地址，不把用户普通文本中的 URL 当作原图。
- 引用没有提供原图时，按 QQ 消息索引回查本群当前角色已收到的消息；不会跨群、跨角色查询。原图没收到、缓存过期或已清理时，需要重新发送原图。

## 按需读取最近群聊

在 `.env` 设置 `QQ_OBSERVE_GROUP_MESSAGES=true`，并在 QQ 侧启用对应的接收全部群消息权限，然后更新 gateway。此开关不能替代 QQ 侧授权。

普通群消息只保存到独立的最近消息表，不调用模型、不主动回复、不自动计分，也不触发摘要。模型需要了解刚才的群聊时可调用 `recent_messages`：默认最近 10 条，可取 1～20 条，按时间排列，排除当前消息，JSON 结果最多 6000 字符。

记录仍按群和角色隔离，默认保留 30 天；用于引用回查的图片及文件地址只使用最近 1 小时的缓存，下一次写入时清理过期地址。工具输出仅包含文本、成员标识、昵称、时间、机器人标记和图片数量，不含附件链接或 QQ 原始消息索引。群消息内容视为不可信背景资料。

## JSON 文件导入

`.json` 文件名或 `application/json` / `text/json` MIME 的附件单独识别，不作为图片。私聊实际收到的 JSON 文件触发预览；群内需引用文件并 @发送 `/导入`。旁听消息仅缓存附件元信息，不下载或自动导入。只收到引用索引时，可回查本会话、当前角色最近收到的文件；附件缺失时提示改用管理 API。

文件由 Gateway 下载，限制 8 MiB，复用公开网络地址检查与 QQ CDN 凭据隔离，不接受普通文本里的 URL。预览与确认使用同一存储流程，10 分钟过期，绑定发起成员和会话；提交重新检查权限及版本。完整格式见 [导入说明](IMPORT.md)。真实附件是否投递仍需在所用 QQ 机器人环境验收。

`/重置上下文` 同时清理当前角色的聊天、摘要和最近消息，保留人设、世界书、记忆及角色状态。旧版本已保存的历史不追溯搬动。

## 看图、改图和发送图片

- QQ CDN 图片由 gateway 使用 QQ 凭据下载；worker 不持有 QQ AppSecret。仅向受限的 HTTPS QQ CDN 地址附加 QQ 令牌，不向第三方站点或重定向目标转发令牌。
- 当前轮看图使用下载后的图片数据；历史轮次不重复加载过期 QQ 图片链接，图片内联数据不写进聊天历史。
- 支持 PNG、JPEG、WebP、GIF。原始文件上限 10 MiB、4000 万像素；超过这两项硬限制仍会拒绝。
- 改图输入自动等比缩放到最长边 2048、上传体积不超过 8 MiB；需要转换时转为 PNG 并保留透明度。GIF 改图使用第一帧。
- 生成结果超过本项目 QQ 直传预算 5 MiB 时自动缩放、重编码；仍保留 10 MiB 下载和 4000 万像素解码上限。需要缩小的 GIF 输出会变为静态 PNG。
- 看图每轮最多处理前 5 张并提示超出部分。改图工具可通过 `image_index` 选择原图、引用图或本轮刚生成的图片，序号从 0 开始。模型不能指定任意图片下载地址。
- 生图使用 `IMAGE_MODEL`；可选 `IMAGE_EDIT_MODEL` 单独指定改图模型，留空时沿用生图模型。更新配置后重建 worker。

```dotenv
IMAGE_BASE_URL=http://sub2api:8080/v1
IMAGE_API_KEY=替换为接口密钥
IMAGE_MODEL=gpt-image-2.5-sunburst
IMAGE_EDIT_MODEL=gpt-image-2.5-flare
```

这只是配置示例，模型名必须由自己的服务实际提供。

## 回复与连接恢复

普通文本保持文本消息；包含 Markdown 语法时使用 QQ Markdown 消息格式。长回复分段，并继续遵守被动回复时间、次数和持久化幂等限制。媒体先上传，再发送包含 file_info 的消息。

QQ 明确返回 401 时刷新令牌并重试一次；明确限流时只进行一次有界等待重试。网络中断、5xx 或结果不确定时不自动重发。日志只记录 QQ HTTP 状态和错误码，不记录聊天正文和凭据。

WebSocket 会话与已入队事件序号保存在 gateway 数据库中，重启后尝试 Resume；会话失效时重新鉴权。事件持久化到 Redis 后才推进游标。

## 共享 Docker 网络

worker 连接已有 SearXNG/sub2api 网络时，若该网络存在其他项目的 redis 或 gateway，必须使用唯一主机名。服务器覆盖配置示例（项目名为 qq-traven）：

```yaml
services:
  worker:
    environment:
      REDIS_URL: redis://qq-traven-redis-1:6379/0
      GATEWAY_URL: http://qq-traven-gateway-1:8080
```

当前 worker 数据库迁移到 schema 4，包含最近消息、实例权限、导入暂存及管理审计。升级前停止 worker 并完整备份数据卷；首次升级后 QQ 手动修改默认关闭。回滚时恢复匹配的旧镜像和数据库备份。
