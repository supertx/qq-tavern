# 批量导入角色与世界观

导入文件使用本项目的 `qq-tavern.bundle` v1 JSON。下载 [完整示例](examples/tavern.bundle.json)，或按照 [JSON Schema](import.schema.json) 生成。README 提供了[可复制给 AI 的整理提示词](../README.md#让-ai-整理角色与世界观)。

## 整理与更新规则

文件采用 UTF-8，可带 BOM，最大 **8 MiB**，每批 1～100 个角色。只支持此标准 JSON；Word、PDF、TXT、PNG 角色卡和第三方酒馆导出文件需要先由 AI 或其他工具整理成该格式。机器人不会把文件交给模型自动解释。

```json
{
  "format": "qq-tavern.bundle",
  "version": 1,
  "roles": [
    {
      "name": "星灯",
      "character": {"description": "山间书屋的向导"},
      "note": "使用简体中文",
      "worldbook": {
        "budget_chars": 6000,
        "entries": [
          {"title": "世界观", "content": "山路随晨雾改变。", "constant": true},
          {"title": "北山驿站", "content": "驿站已经关闭多年。", "keywords": ["驿站", "北山"]}
        ]
      }
    }
  ]
}
```

- `name` 精确匹配**目标会话**内的档案名。相同名字更新，找不到则新建；同批次不能重名。角色名 1～100 字，不能换行或有首尾空白。
- `character` 可提供 `name`、`description`、`personality`、`scenario`。导入中的 `character.name` 若提供必须等于外层 `name`；改名请用配置 API 或 QQ 命令。
- 同名角色只更新明确提供的字段，省略即保留。字符串 `""` 可以清空对应人设或规则。新角色默认空白人设、空世界书、预算 6000、自带默认状态项。
- `note` 为公共规则／作者注释。角色描述、性格、场景合计最多 12000 字；规则最多 6000 字。
- 提供 `worldbook.entries` 时**整体替换**该角色世界书，`[]` 表示清空。只更新预算时省略 `entries`。每角色最多 200 条，条目编号由服务重新生成，不接受 `id`。
- 每条必须提供非空 `title`（最多 100 字）和 `content`（最多 6000 字）；默认 `enabled: true`、`priority: 50`、`constant: false`。优先级为 0～100。
- 世界观设为 `constant: true` 的常驻条目；细节资料可使用 `keywords`，任一个命中就参与注入。非常驻条目至少一个关键词，每条最多 20 个、每个最多 100 字。
- `budget_chars` 为 0～24000 字符，0 暂停世界书注入。常驻条目也受预算限制，并不保证每轮全部注入。
- 不接受 `null`、未知字段、重复 JSON 键或额外 JSON 文档。报错会指出角色／条目位置；Schema 之外，服务还会检查合计字符长度、角色重名及现有数据。

导入保留聊天历史、摘要、个人记忆、状态定义、状态值和当前角色选择。本期文件不包含状态定义；使用管理 API 单独配置。

## 在 QQ 中导入

首次部署或升级后所有手动修改命令默认关闭。部署者先通过 [管理 API](ADMIN_API.md) 开放所需命令组：

| 内容 | 所需命令组 |
| --- | --- |
| 新建角色或修改人设 | `role_edit` |
| 公共规则、世界书、预算 | `world_edit` |
| 导入后通过 QQ 切换角色 | `role_switch` |

一次导入涉及多个组时必须全部开放；只更新已有角色世界书不要求开放角色编辑。权限对本实例所有群、私聊成员生效。

1. 私聊：直接把 `.json` 文件作为文件发给机器人。
2. 群聊：先发送文件，然后**引用该文件消息并 @机器人**发送 `/导入`。群旁听只缓存附件信息，不自动下载或导入。
3. 检查预览的新增／更新角色、修改字段、世界书数量。批量角色较多时 QQ 只展示前 12 个，完整清单请使用 API。
4. 10 分钟内在原会话发送 `/导入 确认 编号`，或 `/导入 取消 编号`。只有发起预览的成员能操作该预览。
5. 保存成功后，用 `/角色 列表` 查看，再执行 `/角色 切换 星灯`（需角色切换权限），或通过 API 选择角色。

QQ 必须实际投递文件附件或可回查的引用信息；只粘贴文件 URL 不会下载。文件附件缓存地址仅使用最近 1 小时的记录，并受会话与角色隔离限制。若附件没有投递、引用丢失或下载链接失效，重新发送文件；仍不可用时改用 API。图片继续走图片流程，不作为导入文件。

## 通过 API 导入

向 `POST /api/admin/v1/scopes/{scope}/imports/preview` 提交原始 JSON。预览返回 `id`、UTC `expires_at` 和 `changes`。检查后调用 `POST /api/admin/v1/scopes/{scope}/imports/{id}/commit`；取消使用 `DELETE /api/admin/v1/scopes/{scope}/imports/{id}`。完整的 PowerShell 和 curl 命令见 [管理 API](ADMIN_API.md)。

预览不修改角色。确认时重新检查所有目标配置版本；QQ 预览还检查最新命令组权限。任一角色版本改变、同名新角色被其他操作创建或权限关闭时，**整批不保存**。冲突后重新预览；不要自动确认新的预览。

每个发起者在一个会话、一个入口最多保留 8 个待确认预览，10 分钟后过期。API 和 QQ 预览不能互相确认。成功提交后重复确认同一个编号返回原结果，不重复创建或修改。取消和过期的预览不能提交。管理 API 已鉴权的导入不受 QQ 开关限制。
